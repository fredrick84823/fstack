# 給會議成員：把錄音丟進來，記錄自己出現

寫給**丟錄音的人**，不是維運的人。一頁講完：丟哪、多久會出現、沒出現會怎樣、
哪些會議不要丟進來。

目前開放的範圍是 **PM team 的會議**。其他部門要上線還要手動加設定，PoC 階段先不開。

---

## 1. 丟哪

錄音要放進**該場會議的日期資料夾**，不是丟在系列資料夾的最外層。

```
{Shared Drive}
└── {你們的系列資料夾}          ← 已經在用的那個
    └── 20260921/               ← 這一層要自己開，名字就是 8 位數的日期
        └── 錄音檔.m4a
```

日期資料夾**不存在就自己開一個**，名字是會議當天的 `YYYYMMDD`（例：2026-09-21 → `20260921`）。
檔名不重要，系統看的是資料夾名。

> **這一層對大家是新習慣。**
> 2026-09-21 實測掃過五個部門的系列資料夾，底下躺著 101 個音檔，全部直接放在系列資料夾
> 根目錄、沒有日期資料夾（最舊的是 2026-02）。也就是說「先開一個日期資料夾」不是既有
> 習慣，是這次要新養的那一步 —— 也是最容易漏掉的一步。

丟錯層會怎樣：

| 你做的 | 結果 |
|---|---|
| `{系列資料夾}/{YYYYMMDD}/錄音` | ✅ 會產 |
| `{系列資料夾}/{YYYYMMDD}_{場次}/錄音` | ✅ 會產（見下一節） |
| `{系列資料夾}/錄音`（直接丟最外層） | ❌ 不產。沒有日期就不知道是哪一天的會議。會議 channel 會收到一則提醒，請你把它移進日期資料夾 —— **這件事只有你做得到**，移完下一輪就會自己產 |
| 同一個資料夾放兩個音檔 | ❌ 不產。系統不會替你猜哪一個才是。請照下一節各開一個資料夾 |
| 資料夾名不是 `YYYYMMDD` 也不是 `YYYYMMDD_場次` | ❌ 不產。裡面有錄音的話會提醒你，名字改對就好 |

## 2. 一天兩場以上

**各開一個資料夾，不要塞同一個。** 後綴就是場次名：

```
{系列資料夾}/
├── 20260921_am/     ← 上午那場的錄音
└── 20260921_pm/     ← 下午那場的錄音
```

後綴用小寫英數、中文、底線或短橫線都可以（`am`／`pm`／`project-x`）。
`morning` `am` `noon` `afternoon` `pm` `evening` 這幾個系統排得出一天之中的先後，
其他名字排在已知場次後面。

## 3. 多久會出現

排程在**每小時的 :30** 掃一次。2026-09-21 實測完整跑過一場：

```
16:30            16:31                                        16:43
  │                │                                            │
  ├─ 排程觸發 ─────┼─ 掃到你的檔 ──── 產記錄 ─────────────────────┤
                                                    Slack 貼出連結
                   └──────────── 約 13 分鐘 ────────────────────┘
```

所以實際等待時間 =（到下一個 :30 還有多久）＋ 約 13 分鐘。
剛好錯過 :30 的話，最久大約 1 小時 15 分。**這是實測值，不是理論值。**

記錄產好會直接貼到該會議的 Slack channel，附 Google Doc 連結。

## 4. 沒出現會怎樣

**你不用做什麼。**

該會議的 Slack channel 會收到一則提醒，講三件事：哪一場、為什麼（人話）、
以及「已經有人收到通知會去處理，不需要做任何事」。同一場同一個原因**一天只發一則**。

修復的負責人是**這套系統的維運者**。看到提醒不用私訊追，也不用重丟一次檔案 ——
重丟只會變成「同一個資料夾兩個音檔」，反而讓它更不會產。

唯一的例外是**放錯層**那則（📥 開頭的那個）：那則要請你自己把檔案移進日期資料夾，
因為沒有人知道那是哪一天的會議。

## 5. 敏感會議不要丟進來

規則只有一條，看**資料夾**，不看檔名：

- **要自動產記錄** → 放進已經登記的系列資料夾
- **不想被自動處理** → 放在排程憑證讀不到的資料夾（你個人的雲端硬碟，或沒有分享給排程帳號的資料夾）

排程會讀取每一個登記過的系列資料夾底下最近 7 天的內容，並把產出的記錄
**貼到該會議的 Slack channel**。所以人資、薪酬、考績、合約、資遣、法務這類會議的錄音，
**不要放進登記的資料夾** —— 一旦放進去，記錄會自己產出來並公開貼到 channel，
沒有「事後標記為機密」這個選項。

不確定某個資料夾有沒有被登記 → 先問維運者，不要先丟。

## 6. 記錄裡的人名是推定的，不是逐字稿標記

**讀記錄的人要知道這件事。**

逐字稿本身**沒有任何發言者標記** —— 語音轉文字交出來的是一整段連續的文字，
不帶「這句是誰講的」。記錄裡看到的人名，是依設定檔裡的**報告順序**推出來的。

所以：

- 順序照走的會議，人名大致對得上
- 有人插話、臨時換順序、或**與會者名單漏了某個人**，那個人講的話會被併到當時正在報告的人身上

這不是假設。2026-09-16 那場，與會者名單漏掉了一位被報告的對象，
他整場的提問與裁決全部被算到當時正在報告的那個人頭上。

引用記錄裡的一句話去追人之前，先回頭聽那段錄音。
發現人名錯了，跟維運者說一聲，把人補進設定檔就好。
