# Slack RD sync

**母訊息是公告，thread 是論述。兩種文體，不是同一段話的長短版本。**

寫給工程同事的訊息預設會失敗的方式跟寫給 PM 相反：收件人看得懂每個字，所以作者忍不住把理由一起寫進去。但公告的讀者是在捲頻道，他要的是「這件事有沒有要我動手」；想知道為什麼的人會點進 PR。

```
母訊息（公告）          6–8 行。標題 / TL;DR / 連結 / 一段落地資訊
  └─ thread（論述）      可以長。為什麼這樣做、帶到下一步
```

**PR、ADR、issue 上已經有的資訊，Slack 一律不重複。** 訊息可以短，是因為背後有東西可追。

## 交付是 draft

Slack 送出後沒有 edit 工具，所以這個 skill 的產出是一份待審稿。

1. **公告**用 `slack_send_message_draft(channel_id, message)` 落到頻道草稿，把回傳的 `channel_link` 給使用者。
2. **論述**在回覆裡貼全文給使用者看。thread draft 需要 parent `ts`，公告還沒送出就還不存在。
3. 使用者明說要送，才 `slack_send_message`。公告送出拿到 `ts` 後，論述用 `thread_ts` + `reply_broadcast: true`。

一個頻道只能掛一份 draft，撞到 `draft_already_exists` 就把公告全文貼在回覆裡，並告訴使用者頻道已有舊草稿。

完成條件：使用者手上同時有公告的 `channel_link`（或全文）與論述全文，且沒有任何訊息被送進頻道。

## 母訊息

1. **標題一行。** `📢 <主題A> + <主題B>`。兩件事以內，第三件另發。

2. **`*TL;DR*` 一行當標籤，下面接 `>` blockquote，`•` bullet，一項一行。** 每項是一個可觀察的事實或一個動作，不附理由。想寫「因為…」就是該進 thread 的東西。

3. **連結一行**，緊貼 TL;DR，不空行。`細節都在 PR：<主題> ｜ #NNN → #NNN`

4. **落地資訊一段。** 下一步在哪、什麼時候、誰要動。沒有就省略。

完成條件：母訊息每一行都是事實、動作或連結。出現「因為」「理由是」「這代表」就搬進 thread。

## thread

論述在這裡展開，**不要砍到只剩結論**。反而要補結構：

1. **小標題** `*…*` 分段。一段一個論點。
2. **最關鍵的那一句包進 `>` blockquote。** 一則 thread 只挑一句，多了就沒有重點。
3. **並列清單抽成 code block。** 兩項以上的 PR 編號、service 名、檔案路徑，`​```` 區塊一行一項，不要內嵌成一長串。
4. **因果鏈用逗號串成長句**，不要句號切碎。「已經在服務真實流量，但 main 上看不到，繼續卡著 PR 並不會讓那些碼下線，只會讓 main 越來越不代表現實。」
5. **結尾帶到下一步**，並說清這次做完之後**還沒解決什麼**。

## 語氣

陳述事實，不用第一人稱包裝。「優先度最高」不是「我認為要優先」。「以前會安靜地綠」不是「我發現以前會安靜地綠」。

引號標出被評價的那句話本身：`理由是「這些碼早就在線上跑了」`。

讀者自己決定他要讀什麼，不下閱讀指令。

## Slack 格式

| 要的 | 語法 |
|---|---|
| 粗體 | `*文字*`（單星號，不是 `**`） |
| TL;DR / 關鍵句 | `>` blockquote |
| 清單 | `•`（blockquote 內）或 `-`（code block 內） |
| 並列項目 | ` ``` ` code block |
| 編號 | 用 `•`，不用 1️⃣2️⃣3️⃣ |

## 判準

| 徵狀 | 位置 |
|---|---|
| 母訊息超過八行 | 論述沒搬進 thread |
| 母訊息出現「為什麼…」小標題 | 同上 |
| TL;DR 某一項超過一行 | 那項的理由該進 thread |
| thread 只有三句結論 | 砍過頭了，補小標題與 blockquote |
| 同一件事 PR 上寫過又在 Slack 寫一遍 | 刪掉，只留連結 |
| 出現「我認為」「我發現」 | 改成陳述 |
| 直接呼叫 `slack_send_message` | 使用者還沒審稿，改 draft |

需要一份改寫前後的完整對照時，看 [`references/examples.md`](references/examples.md)。
