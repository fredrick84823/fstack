# Brainstorming Techniques — MVP

MVP 四個明星技巧的完整執行指引。
Claude 在 Stage 2 選定技巧後，依此文件推進 Facilitation。

---

## W1 — What-if Scenarios（發散）

**適用情境**：想探索「如果 X 不一樣，會發生什麼？」、打開可能性空間、突破預設條件。

**執行步驟**：

1. 請使用者說出目前對主題的「預設假設」（例：用戶需要登入才能使用）
2. Claude 拋出第一個 What-if 問題，改變其中一個假設
3. 等使用者回應 → 追問「這會帶來什麼？」「有什麼障礙？」
4. 重複 2–4 輪，每輪挑戰不同的假設
5. 收整：哪個 What-if 最讓你興奮或最難回答？

**Probing Question 範例**：
- 如果時間或預算無限，你會怎麼做？
- 如果目標用戶完全改變（例如換成小孩或 80 歲老人），會怎樣？
- 如果這個功能消失了，用戶會有什麼替代方案？
- 如果現有技術全部不能用，你會用什麼方式解決？
- 如果這件事要讓 10 倍的人使用，什麼會先壞掉？

**產出格式**：
```
What-if 清單：
- 若 [改變 A]，則 → {使用者想法}
- 若 [改變 B]，則 → {使用者想法}
...
最有潛力的 What-if：[使用者選出的]
```

## W2 — SCAMPER（發散+框架混合）

**適用情境**：手上有一個現有的東西（產品、流程、功能），想系統性改良或衍生新想法。

**SCAMPER 七個維度**：

| 字母 | 操作 | 問法 |
|------|-----|------|
| S — Substitute | 替換某個元素 | 可以用什麼替代？ |
| C — Combine | 合併兩個東西 | 和什麼結合會更好？ |
| A — Adapt | 從其他領域借鑑 | 哪個領域已經解決了類似問題？ |
| M — Modify/Magnify | 放大或強調 | 如果把某個特性放大 10 倍？ |
| P — Put to other uses | 用在其他用途 | 這個東西還可以解決什麼問題？ |
| E — Eliminate | 移除某個元素 | 拿掉哪個部分還能運作？ |
| R — Reverse/Rearrange | 顛倒或重排 | 反過來做會怎樣？ |

**執行步驟**：

1. 請使用者描述要 SCAMPER 的對象（是什麼？目前如何運作？）
2. Claude 選 2–3 個最適合當前主題的維度開始問
3. 每個維度問一個具體問題，等回應後追問
4. 不需要跑完全部 7 個，以產生新想法為目標
5. 收整：哪個操作帶出最有趣的方向？

**Probing Question 範例**：
- (S) 如果把「資料庫」換成「用戶的手機記憶體」？
- (C) 如果把「分析功能」和「推薦功能」合併成一件事？
- (E) 如果拿掉「登入」這個步驟，流程會變成什麼？
- (R) 如果讓用戶先看結果、再告訴系統為什麼？

**產出格式**：
```
SCAMPER 結果：
- [S] 替換嘗試 → {想法}
- [C] 合併嘗試 → {想法}
- [E] 移除嘗試 → {想法}
最有潛力的方向：{使用者選}
```

## R1 — Reverse Brainstorming（反向思考）

**適用情境**：正面想法想不出來、想找盲點、想打破既有框架、或想測試某個方案的弱點。

**核心邏輯**：先問「怎麼讓這件事徹底失敗？」，再把答案反轉成改善方向。

**執行步驟**：

1. 確認使用者的目標（例：讓用戶持續使用這個 app）
2. Claude 帶頭問：「怎麼做才能確保用戶最快離開？」
3. 使用者列出 3–5 個「讓事情變糟」的做法
4. Claude 幫忙把每個「壞做法」反轉成改善行動
5. 追問：反轉後哪些是你沒想到的盲點？

**Probing Question 範例**（反向版）：
- 怎麼設計才能讓用戶覺得最浪費時間？
- 什麼設計能確保新用戶第一次用就放棄？
- 如果要讓這個功能被投訴最多，你會怎麼做？
- 什麼是你現在的做法裡最接近「讓事情變糟」的部分？

**反轉操作**：
```
壞做法：[X]
→ 反轉：不要 [X]，改成 [反面]
→ 這提醒我：[洞察]
```

**產出格式**：
```
Reverse Brainstorming 結果：
壞做法 1：→ 反轉 → 洞察
壞做法 2：→ 反轉 → 洞察
...
最關鍵的盲點：{使用者選}
```

## F1 — First Principles（框架：第一原理）

**適用情境**：問題卡住、被既有方案框住、想從零重建思路、或要挑戰「這就是行規」的假設。

**核心邏輯**：把問題拆解到最基本的「不可再分」事實，再從這些事實重新推論解法。

**三步走法**：

1. **識別假設**：你對這個問題有什麼「大家都這樣做」的預設？
2. **拆解到基本事實**：把每個假設問到底，問「這個是必然的嗎？」直到找到真正的物理/邏輯限制
3. **從基本事實重建**：只用這些基本事實，重新想解法

**執行步驟**：

1. 請使用者用一句話說問題
2. Claude 問：「你現在的解法是什麼？它背後最大的假設是什麼？」
3. 針對最大假設追問：「這個假設是必然的嗎？如果不是，限制是什麼？」
4. 找到「真正的限制」後問：「如果只有這些限制，你會怎麼從零開始解？」
5. 迭代 2–3 輪，每輪更深一層

**Probing Question 範例**：
- 你說「這樣做太貴」——貴在哪裡？成本的根本構成是什麼？
- 你說「用戶不會接受」——你怎麼知道？有沒有反例？
- 如果完全不考慮現有系統，最簡單能解決核心問題的方法是什麼？
- 什麼是你確定是真的、不能改變的？什麼是「大家都這樣做所以才這樣」？

**產出格式**：
```
First Principles 分析：
問題核心：{一句話}

識別的假設：
- [假設 A] → 真正的限制：{是/否，以及為什麼}
- [假設 B] → 真正的限制：{是/否，以及為什麼}

從基本事實重建的解法：
- {解法 1}
- {解法 2}
```
