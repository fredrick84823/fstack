# 四種工程圖

這幾種的共通點：**空間位置帶有意義**。前後、相鄰、對齊本身就是資訊，所以欄位算錯不只是難看，是講錯話。

## memory layout / 位元欄位

橫軸是位址或 bit 序，每格寬度要與它代表的大小成比例，否則圖在說謊。刻度尺放在框外。

```
 0        8        16       24       31
 ├────────┼────────┼────────┼────────┤
 │ version│  IHL   │      total_len   │
 ├────────┴────────┼────────┬─────────┤
 │       id        │ flags  │ frag_off│
 ├─────────────────┴────────┴─────────┤
 │              source_addr           │
 └────────────────────────────────────┘
```

不等寬的欄位是唯一例外：欄寬可以不成比例，但要在圖旁註明實際 bit 數。

## 網路拓樸 / 部署

分層由上往下，同層對齊。跨層的線只走垂直與水平，轉角用 `┬ ┴ ├ ┤`。

```
                    ┌──────────────────┐
                    │   claude.ai      │
                    └────────┬─────────┘
                             │ OAuth + MCP
                    ┌────────┴─────────┐
                    │  api-gateway     │  production 5/5
                    └────────┬─────────┘
              ┌──────────────┼──────────────┐
              │              │              │
        ┌─────┴─────┐  ┌─────┴─────┐  ┌─────┴─────┐
        │ docs-api  │  │ sheets    │  │ events    │
        └─────┬─────┘  └───────────┘  └───────────┘
              │ runtime SA（零 project role）
        ┌─────┴──────────┐
        │  Google Drive  │
        └────────────────┘
```

信任邊界用虛線 `╌╌╌` 或註記，不要用不同粗細的框 —— 等寬字型裡看不出差別。

## 資料結構

指標用 `──→` 指向目標框的左邊界，不要指向框中央。`null` 寫出來，不要留空。

```
 head
  │
  ↓
┌──────┬───┐   ┌──────┬───┐   ┌──────┬──────┐
│ 0x1a │ ●─┼──→│ 0x2b │ ●─┼──→│ 0x3c │ null │
└──────┴───┘   └──────┴───┘   └──────┴──────┘
```

## 時間軸 / 甘特

每欄一個固定時間單位，欄寬一致。條狀用 `█` 或 `━`，兩者不混用。里程碑用 `◆`。

```
              9/1   9/3   9/5   9/7   9/9
              ├─────┼─────┼─────┼─────┤
spec #12      ████████████████◆
production                    ██████◆
CD 上線                             ███◆
#19 補樣本                             ╌╌╌╌  未排
```

單位不等距（例如「上週 / 本週 / 下季」）就不要畫時間軸，改用表格 —— 等距的欄位會讓讀者以為時間也等距。
